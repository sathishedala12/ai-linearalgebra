Foundations & the estimator API

scikit-learn's secret weapon is consistency. Once you understand the estimator API, every model in the library — from linear regression to gradient boosting to PCA — behaves the same way.

The three contracts every object follows

An estimator is any object that learns from data. It always has a .fit() method. Then depending on what it does, it implements one or more of these:

MethodWho has itWhat it does
.fit(X, y)everythinglearn parameters from data; modifies the object in-place and returns self
.predict(X)classifiers, regressorsproduce labels or numbers for new data
.predict_proba(X)most classifiersprobability estimates per class
.transform(X)preprocessors, reducersturn X into something new (scaled, encoded, projected)
.fit_transform(X)transformersshortcut: fit then transform — only use on training data
.score(X, y)most modelsbuilt-in metric (R² for regressors, accuracy for classifiers)

The canonical workflow — memorize this shape

from sklearn.linear_model    import LogisticRegression
from sklearn.preprocessing   import StandardScaler
from sklearn.model_selection import train_test_split
from sklearn.datasets        import load_breast_cancer

# 1. Load data
X, y = load_breast_cancer(return_X_y=True)

# 2. Split BEFORE doing anything else (this is the rule)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

# 3. Fit a transformer on TRAIN only, then apply to both
scaler = StandardScaler().fit(X_tr)
X_tr_s = scaler.transform(X_tr)
X_te_s = scaler.transform(X_te)

# 4. Fit the model on TRAIN, evaluate on TEST
model = LogisticRegression(max_iter=1000).fit(X_tr_s, y_tr)
print(model.score(X_te_s, y_te))   # accuracy by default
why split first

If you scale the whole X before splitting, the mean and std are computed using test-set rows. That's data leakage — your test score will be optimistically biased. Fit transformers on train only. A Pipeline (Chapter 11) does this automatically.

Attributes you'll constantly inspect

After .fit(), every estimator stores what it learned in attributes ending with an underscore (sklearn convention: name_ means "learned from data"):

model.coef_              # LogisticRegression weights
model.intercept_         # bias term
model.classes_           # label order in predict_proba columns
model.feature_names_in_  # names if X was a DataFrame
model.n_features_in_     # expected input width

scaler.mean_, scaler.scale_    # StandardScaler's learned stats
pca.components_, pca.explained_variance_ratio_
mental model

Think of every sklearn object as a tiny stateful program. Before .fit() it knows nothing. After .fit() it carries the learned state. .predict() and .transform() just apply that state.

Getting data: built-in datasets

Before plumbing in real data, sklearn ships toy and synthetic datasets perfect for learning and prototyping. There are three families: loaders (toy, bundled), fetchers (download once, cache), and generators (synthetic, parameterized).

Toy loaders — built into the package

from sklearn.datasets import (
    load_iris,            # 150 flowers, 3 classes — classic classification
    load_breast_cancer,   # 569 tumors, binary — best toy for medical-style
    load_wine,            # 178 wines, 3 classes
    load_digits,          # 1797 8×8 handwritten digits
    load_diabetes,        # 442 patients — regression
    load_linnerud,        # multi-output regression
)
data = load_iris()
X, y = data.data, data.target            # numpy arrays
print(data.feature_names, data.target_names)
print(data.DESCR)                       # every loader has a description

# Or get just the arrays:
X, y = load_iris(return_X_y=True)
# Or as a pandas DataFrame:
df  = load_iris(as_frame=True).frame

Fetchers — bigger, real-world data

from sklearn.datasets import (
    fetch_california_housing,  # ~20k rows, regression
    fetch_20newsgroups,        # text classification
    fetch_openml,              # thousands of datasets by name/id
    fetch_lfw_people,          # face images
)

# Famous MNIST via OpenML:
mnist = fetch_openml("mnist_784", version=1, as_frame=False)
X, y = mnist.data, mnist.target.astype("int8")

Generators — synthetic data you control

Generators are how you debug and test. Want to know if your model handles class imbalance, noisy features, or 50 useless columns? Generate the exact problem.

from sklearn.datasets import (
    make_classification,  # the workhorse
    make_regression,
    make_blobs,           # nice round clusters
    make_moons,           # two interleaved half-circles (non-linear)
    make_circles,         # concentric circles (very non-linear)
    make_friedman1,       # classic regression benchmark
)

X, y = make_classification(
    n_samples=5000,
    n_features=20,
    n_informative=8,     # 8 features actually carry signal
    n_redundant=4,       # 4 are linear combos of the informative ones
    n_classes=3,
    weights=[0.7, 0.2, 0.1],     # imbalanced
    flip_y=0.02,         # 2% label noise
    random_state=42,
)
use it for

Reproducing problems on Stack Overflow, sanity-checking a pipeline before throwing real data at it, and benchmarking new ideas in a controlled environment.

03

Train/test split & cross-validation

A single train/test split gives you one noisy estimate of model performance. Cross-validation gives you k of them, drastically reducing variance and surfacing whether your model is consistent.

train_test_split — the basics

X_tr, X_te, y_tr, y_te = train_test_split(
    X, y,
    test_size    = 0.2,        # 20% held out, or pass an integer for absolute count
    train_size   = None,       # inferred from test_size
    stratify     = y,          # preserve class proportions (ALWAYS for classification)
    random_state = 42,         # reproducibility
    shuffle      = True,       # DO NOT shuffle time-series
)
stratify

Without stratify=y on a classification problem, especially an imbalanced one, your test set might end up with very different class proportions than train — making metrics meaningless. Just always use it for classification.

Cross-validation: the splitters

A splitter is just an iterator that yields (train_idx, test_idx) pairs. sklearn picks one of these for you when you call cross_val_score, but you can pass any of them explicitly.

KFold — the vanilla one

from sklearn.model_selection import KFold
kf = KFold(n_splits=5, shuffle=True, random_state=42)
for tr_idx, te_idx in kf.split(X):
    X_tr, X_te = X[tr_idx], X[te_idx]

StratifiedKFold — for classification

Same as KFold but preserves class ratios in each fold. Use this any time the target is categorical.

from sklearn.model_selection import StratifiedKFold
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

GroupKFold — when rows aren't independent

Imagine medical data with multiple visits per patient. If patient X has rows in both train and test, your model can cheat by memorizing patient-level patterns. Pass groups=patient_id to keep each patient entirely in one fold.

from sklearn.model_selection import GroupKFold
gkf = GroupKFold(n_splits=5)
for tr_idx, te_idx in gkf.split(X, y, groups=patient_id):
    ...

TimeSeriesSplit — never train on the future

For temporal data. Each fold's training set is a prefix of time; test is the next chunk. Mimics how the model will be used in production.

from sklearn.model_selection import TimeSeriesSplit
tscv = TimeSeriesSplit(n_splits=5, test_size=200, gap=10)
# gap=10 leaves a 10-step buffer between train and test (anti-leakage)

Others worth knowing

  • RepeatedKFold / RepeatedStratifiedKFold — run k-fold N times with different seeds; reduces variance further.
  • LeaveOneOut — k = n. Only for tiny datasets; slow.
  • ShuffleSplit / StratifiedShuffleSplit — random repeated holdouts (test sets can overlap).

Running cross-validation

from sklearn.model_selection import cross_val_score, cross_validate, cross_val_predict

# 1. Single metric, fast
scores = cross_val_score(model, X, y, cv=5, scoring="f1_macro", n_jobs=-1)
print(f"{scores.mean():.3f} ± {scores.std():.3f}")

# 2. Multiple metrics + timing + train scores
result = cross_validate(
    model, X, y, cv=5,
    scoring=["accuracy", "f1_macro", "roc_auc_ovr"],
    return_train_score=True,
    return_estimator=True,    # keep each fold's fitted model
    n_jobs=-1,
)

# 3. Out-of-fold predictions (useful for stacking, error analysis)
y_oof = cross_val_predict(model, X, y, cv=5, method="predict_proba")

Preprocessing: scaling, encoding, imputing

Most ML wins come from preprocessing, not from picking a fancier model. Each transformer here learns parameters from training data and applies them consistently to test data.

Scaling numeric features

Many models (linear, SVM, KNN, neural nets, PCA) are scale-sensitive — a feature with values in millions will dominate a feature with values in 0-1. Tree-based models (Random Forest, Gradient Boosting) are scale-invariant; don't bother scaling for them.

ScalerWhat it doesUse when
StandardScalersubtract mean, divide by std → mean 0, std 1default for most things
MinMaxScalersquish to [0, 1] linearlyneural nets, image-like data, when you need bounded values
RobustScaleruses median & IQR instead of mean & stdheavy outliers you can't remove
MaxAbsScalerdivide by max absolute value → [-1, 1]sparse data (preserves zeros)
Normalizerscales each row to unit normtext vectors, cosine-similarity workflows
PowerTransformerYeo-Johnson or Box-Cox transform → make distribution more Gaussianskewed features feeding linear models
QuantileTransformermap values onto uniform or normal distribution via quantileshighly non-linear distributions, heavy tails
 
from sklearn.preprocessing import StandardScaler, PowerTransformer

sc = StandardScaler()
X_tr_s = sc.fit_transform(X_tr)      # fit + apply in one call
X_te_s = sc.transform(X_te)           # reuse learned mean/std

pt = PowerTransformer(method="yeo-johnson", standardize=True)
X_pt = pt.fit_transform(X_tr)

Encoding categorical features

Models speak numbers. Categories like "red", "blue", "green" have to become numeric — but how matters.

OneHotEncoder — the default for nominal categories

from sklearn.preprocessing import OneHotEncoder

ohe = OneHotEncoder(
    handle_unknown="ignore",    # test-time unseen category → all zeros
    sparse_output=False,        # dense numpy array (easier to inspect)
    drop="first",                # drop one column to avoid dummy trap (linear models)
    min_frequency=10,             # lump rare categories into an "infrequent" bucket
)
X_ohe = ohe.fit_transform(X_cat)

OrdinalEncoder — when categories have a real order

from sklearn.preprocessing import OrdinalEncoder
oe = OrdinalEncoder(
    categories=[["low","medium","high"]],   # explicit order
    handle_unknown="use_encoded_value",
    unknown_value=-1,
)

TargetEncoder — for high-cardinality categoricals (1.3+)

Replace each category by a smoothed mean of the target. Powerful for things like zip_code with thousands of unique values — one-hot would explode dimensionality.

from sklearn.preprocessing import TargetEncoder
te = TargetEncoder(smooth="auto", target_type="binary")
X_te_enc = te.fit_transform(X_cat, y)

LabelEncoder — only for the target y

Common mistake: people use LabelEncoder on features. Don't — it's strictly for the y vector. Use OrdinalEncoder for feature columns.

Imputing missing values

Most sklearn models reject NaN. (Exceptions: HistGradientBoosting* handle NaN natively.) Three imputers:

from sklearn.impute import SimpleImputer, KNNImputer
from sklearn.experimental import enable_iterative_imputer  # noqa
from sklearn.impute import IterativeImputer

# Simple: constant strategy per column
imp = SimpleImputer(strategy="median")     # or "mean", "most_frequent", "constant"

# KNN: fill each missing value using the k nearest rows
imp = KNNImputer(n_neighbors=5, weights="distance")

# Iterative (MICE-style): model each feature as a function of the others
imp = IterativeImputer(max_iter=10, random_state=42)
add a flag

Missingness is often informative. SimpleImputer(add_indicator=True) appends a binary "was-missing" column for each imputed feature — your model can learn from the missingness itself.

Other transformers worth knowing

from sklearn.preprocessing import (
    PolynomialFeatures,   # add x^2, x1*x2, etc.
    KBinsDiscretizer,     # turn continuous → categorical bins
    Binarizer,            # 0/1 above a threshold
    FunctionTransformer,  # wrap any function as a transformer
    SplineTransformer,    # non-linear basis expansion for linear models
)

# Add interaction terms
poly = PolynomialFeatures(degree=2, interaction_only=True, include_bias=False)

# Bin a feature into quartiles (encodes as one-hot)
bins = KBinsDiscretizer(n_bins=4, encode="onehot-dense", strategy="quantile")

# Apply log1p as a transformer (so it fits inside a Pipeline)
import numpy as np
log = FunctionTransformer(np.log1p, inverse_func=np.expm1, validate=True)

Classification — every major algorithm

For each algorithm: the intuition, when to use it, and a working example. Knowing which model fits a problem is more valuable than knowing all the hyperparameters of one.

Logistic Regression — the workhorse baseline

Intuition: draw a (possibly hyperdimensional) line that separates classes; output a probability via the sigmoid. Despite the name, it's a classifier. Fast, interpretable, well-calibrated.

Reach for it when: you want a sanity-check baseline, need interpretable coefficients, or have a roughly linearly separable problem with calibrated probabilities.

from sklearn.linear_model import LogisticRegression
m = LogisticRegression(
    penalty="l2",         # also "l1", "elasticnet", or None
    C=1.0,                # inverse regularization — smaller C = more regularization
    solver="lbfgs",        # "liblinear" for L1 small data, "saga" for L1/EN big data
    class_weight="balanced",# auto-weight rare classes
    max_iter=1000,
    random_state=42,
).fit(X_tr_s, y_tr)

m.coef_, m.intercept_             # feature weights — interpretable
m.predict_proba(X_te_s)            # columns ordered by m.classes_
scale first

Logistic regression with regularization is scale-sensitive. Always scale.

K-Nearest Neighbors — memorize, don't generalize

Intuition: to classify a new point, look at the k closest training points and take a vote. No training really happens; everything is at predict time.

Reach for it when: low dimensionality (≤ ~20 features), enough labeled data, local structure matters. Avoid for high-dimensional data (curse of dimensionality kills distance metrics).

from sklearn.neighbors import KNeighborsClassifier
m = KNeighborsClassifier(
    n_neighbors=5,
    weights="distance",  # closer neighbors vote louder than farther ones
    metric="minkowski", p=2,   # Euclidean (p=2) or Manhattan (p=1)
    n_jobs=-1,
).fit(X_tr_s, y_tr)

Naive Bayes — fast, probabilistic, text-friendly

Intuition: apply Bayes' theorem assuming features are conditionally independent given the class. The assumption is usually false, yet it works astonishingly well — especially for text.

from sklearn.naive_bayes import GaussianNB, MultinomialNB, BernoulliNB, ComplementNB

# GaussianNB: continuous features ~ normal per class
GaussianNB().fit(X_tr, y_tr)

# MultinomialNB: count features (bag-of-words)
MultinomialNB(alpha=1.0).fit(X_counts, y)   # alpha = Laplace smoothing

# BernoulliNB: binary features
# ComplementNB: better than MultinomialNB on imbalanced text

Decision Tree — interpretable, prone to overfit

Intuition: ask a sequence of yes/no questions on features, ending at a leaf that votes. Captures non-linear interactions; needs no scaling.

Reach for it when: you need a single interpretable model, or as a building block for forests/boosting.

from sklearn.tree import DecisionTreeClassifier, plot_tree
m = DecisionTreeClassifier(
    criterion="gini",      # or "entropy"
    max_depth=8,           # #1 anti-overfit knob
    min_samples_leaf=20,   # refuse leaves smaller than this
    class_weight="balanced",
    random_state=42,
).fit(X_tr, y_tr)

import matplotlib.pyplot as plt
plot_tree(m, feature_names=names, class_names=["neg","pos"], filled=True)

Random Forest — the tabular default

Intuition: train hundreds of decorrelated decision trees on bootstrap samples with random feature subsets; average their votes. Reduces variance dramatically.

Reach for it when: you need a strong, low-tuning baseline on tabular data. Handles mixed types, missing-ish values, and gives you free feature importances.

from sklearn.ensemble import RandomForestClassifier
m = RandomForestClassifier(
    n_estimators=500,
    max_depth=None,         # let trees go deep; the averaging controls overfit
    max_features="sqrt",     # √n features per split — key to decorrelation
    min_samples_leaf=2,
    n_jobs=-1,
    random_state=42,
    class_weight="balanced_subsample",
).fit(X_tr, y_tr)

m.feature_importances_       # biased toward high-cardinality features

Gradient Boosting — sequential tree wizardry

Intuition: build trees one at a time, each fitting the residual errors of the ensemble so far. Slower to train than a forest, but often higher ceiling.

from sklearn.ensemble import GradientBoostingClassifier, HistGradientBoostingClassifier

# Classic — exact, slower
gbc = GradientBoostingClassifier(
    n_estimators=300, learning_rate=0.05, max_depth=3, random_state=42,
)

# Histogram-based — fast like LightGBM, handles NaN natively, scales to millions
hgb = HistGradientBoostingClassifier(
    learning_rate=0.05,
    max_iter=500,
    max_leaf_nodes=31,
    l2_regularization=0.0,
    early_stopping=True,
    validation_fraction=0.1,
    random_state=42,
).fit(X_tr, y_tr)
modern default

For tabular data above ~10k rows, HistGradientBoosting is usually the strongest single model in sklearn. It rivals XGBoost/LightGBM while staying inside the sklearn API.

AdaBoost — the original boosting

Re-weights misclassified samples each round. Mostly historical interest now; HistGB outperforms it almost everywhere.

from sklearn.ensemble import AdaBoostClassifier
AdaBoostClassifier(n_estimators=200, learning_rate=0.5, random_state=42)

Support Vector Machines

Intuition: find the hyperplane that maximizes the margin between classes; with the kernel trick, project into higher dimensions to handle non-linear boundaries.

Reach for it when: small-to-medium datasets (≤ ~50k rows), high-dimensional features, clear margin between classes.

from sklearn.svm import SVC, LinearSVC

# Non-linear (RBF kernel — default and good)
svc = SVC(C=1.0, kernel="rbf", gamma="scale", probability=True).fit(X_tr_s, y_tr)

# Linear, scales to large data
lsvc = LinearSVC(C=1.0, max_iter=5000, dual="auto").fit(X_tr_s, y_tr)
scale + slow

SVMs are very scale-sensitive and scale poorly (training is roughly O(n²) for non-linear kernels). Always scale; don't use on > ~100k rows.

Discriminant Analysis — LDA & QDA

Generative models that assume each class is Gaussian. LDA assumes shared covariance (linear boundary); QDA allows per-class covariance (quadratic boundary). Surprisingly strong baselines, especially with limited data.

from sklearn.discriminant_analysis import LinearDiscriminantAnalysis, QuadraticDiscriminantAnalysis
LinearDiscriminantAnalysis().fit(X_tr, y_tr)

MLPClassifier — neural network in sklearn

A simple fully-connected net. Fine for learning concepts; for real work use PyTorch/TensorFlow/Keras.

from sklearn.neural_network import MLPClassifier
m = MLPClassifier(
    hidden_layer_sizes=(128, 64),
    activation="relu",
    solver="adam",
    alpha=1e-4,
    learning_rate_init=1e-3,
    max_iter=200,
    early_stopping=True,
    random_state=42,
).fit(X_tr_s, y_tr)

Ensembles of estimators — Voting & Stacking

Combine models that make different kinds of errors. Stacking is usually stronger than voting.

from sklearn.ensemble import VotingClassifier, StackingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier

vote = VotingClassifier(
    estimators=[("lr", LogisticRegression()), ("rf", RandomForestClassifier()), ("hgb", HistGradientBoostingClassifier())],
    voting="soft",   # average probabilities — usually better than "hard"
    weights=[1, 2, 3],
)

stack = StackingClassifier(
    estimators=[("rf", RandomForestClassifier()), ("hgb", HistGradientBoostingClassifier())],
    final_estimator=LogisticRegression(),
    cv=5,                  # OOF predictions feed the meta-learner
    passthrough=False,
)

Regression — every major algorithm

Same playbook as classification: each model has a regression cousin (*Regressor instead of *Classifier). The patterns below cover what's distinct.

Linear regression family

All four below fit y = β·X + intercept; they differ in how they penalize the coefficients.

ModelPenaltyEffect
LinearRegressionnoneplain OLS — overfits easily on collinear features
RidgeL2 (sum of squared coefs)shrinks all coefs toward 0; handles collinearity
LassoL1 (sum of |coefs|)drives some coefs to exactly 0 → feature selection
ElasticNetL1 + L2 mixmiddle ground; l1_ratio controls balance
 
from sklearn.linear_model import LinearRegression, Ridge, Lasso, ElasticNet, RidgeCV, LassoCV, ElasticNetCV

# Auto-tune alpha with built-in CV — usually what you want
r = RidgeCV(alphas=[0.01, 0.1, 1, 10, 100]).fit(X_tr_s, y_tr)
print(r.alpha_, r.coef_)

l = LassoCV(cv=5, n_alphas=100, random_state=42).fit(X_tr_s, y_tr)
print(f"{(l.coef_ != 0).sum()} of {len(l.coef_)} features survived")

Robust regression — when outliers ruin OLS

from sklearn.linear_model import HuberRegressor, RANSACRegressor, TheilSenRegressor
HuberRegressor(epsilon=1.35)        # quadratic loss inside, linear outside
RANSACRegressor(min_samples=0.5)      # fits to random inlier subsets, ignores outliers
TheilSenRegressor()                    # median-of-slopes, very robust

Tree-based regressors

Same models as classification, but predicting continuous values. Same defaults apply.

from sklearn.ensemble import RandomForestRegressor, GradientBoostingRegressor, HistGradientBoostingRegressor
from sklearn.tree     import DecisionTreeRegressor

hgb = HistGradientBoostingRegressor(
    loss="squared_error",    # or "absolute_error" (MAE) for outlier-robust
    max_iter=500,
    learning_rate=0.05,
    early_stopping=True,
).fit(X_tr, y_tr)

Polynomial regression — without a fancy library

Polynomial regression isn't its own model — it's PolynomialFeatures piped into LinearRegression (or Ridge).

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import Ridge

poly = make_pipeline(
    PolynomialFeatures(degree=3, include_bias=False),
    Ridge(alpha=1.0),
).fit(X_tr, y_tr)

SVR & KNN regressors

from sklearn.svm import SVR
from sklearn.neighbors import KNeighborsRegressor

SVR(kernel="rbf", C=1.0, epsilon=0.1)
KNeighborsRegressor(n_neighbors=10, weights="distance")

When the target needs transforming

If y is heavily skewed (income, sales, prices), models predict the mean better when you fit on log(y). TransformedTargetRegressor handles the log/expm1 round-trip automatically.

from sklearn.compose import TransformedTargetRegressor
import numpy as np

reg = TransformedTargetRegressor(
    regressor=HistGradientBoostingRegressor(),
    func=np.log1p,
    inverse_func=np.expm1,
).fit(X_tr, y_tr)
# reg.predict(X_te) returns values in the original scale

Clustering (unsupervised)

No labels, just patterns. The big question is whether you know how many clusters there are.

KMeans — when k is known and clusters are roundish

from sklearn.cluster import KMeans, MiniBatchKMeans

km = KMeans(
    n_clusters=5,
    init="k-means++",    # smart seeding
    n_init="auto",        # try multiple seeds, keep best (default 10)
    max_iter=300,
    random_state=42,
).fit(X_scaled)

km.labels_, km.cluster_centers_, km.inertia_   # inertia = within-cluster SSE

# For huge data, MiniBatchKMeans is ~10–100× faster, slightly worse
MiniBatchKMeans(n_clusters=50, batch_size=1024).fit(X)

Choosing k: elbow + silhouette

from sklearn.metrics import silhouette_score
for k in range(2, 11):
    km = KMeans(n_clusters=k, n_init="auto", random_state=42).fit(X_scaled)
    print(k, km.inertia_, silhouette_score(X_scaled, km.labels_))

DBSCAN & HDBSCAN — density-based, find outliers

Intuition: a cluster is a dense region; sparse points are noise (label -1). You don't pre-specify k.

from sklearn.cluster import DBSCAN, HDBSCAN

db = DBSCAN(eps=0.3, min_samples=10).fit(X_scaled)
# eps = neighborhood radius; min_samples = density threshold

hdb = HDBSCAN(min_cluster_size=20).fit(X_scaled)   # handles varying densities, no eps
use HDBSCAN

If clusters have wildly different densities (which is common in real data), HDBSCAN almost always beats DBSCAN with less tuning.

Agglomerative — hierarchical clusters & dendrograms

from sklearn.cluster import AgglomerativeClustering
ac = AgglomerativeClustering(
    n_clusters=5,
    linkage="ward",       # or "average", "complete", "single"
    metric="euclidean",
).fit(X_scaled)

Gaussian Mixture Models — soft clustering

Each point gets a probability of belonging to each component. Lets you do anomaly detection (low probability under all components = anomaly).

from sklearn.mixture import GaussianMixture
gm = GaussianMixture(n_components=5, covariance_type="full", random_state=42).fit(X)
labels = gm.predict(X)
probs  = gm.predict_proba(X)        # soft assignments
print(gm.bic(X), gm.aic(X))         # model selection criteria — pick n_components by lowest BIC

Other clusterers worth knowing

  • SpectralClustering — great for non-convex shapes (uses graph Laplacian).
  • MeanShift — no k, finds modes of the density. Slow on big data.
  • Birch — hierarchical, scales to huge data via tree summaries.
  • AffinityPropagation — picks exemplars; no k needed; sensitive to damping.
08

Dimensionality reduction

Reduce feature count for speed, denoising, visualization, or feeding into downstream models. The big split: linear (PCA, NMF, SVD) vs non-linear / manifold (t-SNE, UMAP, Isomap).

PCA — the always-try-first one

Intuition: find the orthogonal directions of maximum variance; project onto the top few. Equivalent to an SVD of the centered data.

from sklearn.decomposition import PCA

# Pass a float to keep that fraction of variance:
pca = PCA(n_components=0.95, random_state=42).fit(X_scaled)
X_pca = pca.transform(X_scaled)
print(pca.n_components_, pca.explained_variance_ratio_.sum())

# Or pick an integer count for visualization:
pca2 = PCA(n_components=2).fit_transform(X_scaled)
scale first

PCA is variance-based. Without scaling, a feature with naturally large variance (income vs age) dominates everything. Always StandardScaler before PCA.

TruncatedSVD — PCA's sparse cousin

Same idea, but doesn't center the data — so it works on sparse matrices (tf-idf). Use it after vectorizing text; people call this LSA (Latent Semantic Analysis).

from sklearn.decomposition import TruncatedSVD
svd = TruncatedSVD(n_components=200, random_state=42).fit(X_tfidf)

Other linear options

from sklearn.decomposition import NMF, FastICA, KernelPCA, FactorAnalysis

NMF(n_components=10)            # non-negative — interpretable parts (topics)
FastICA(n_components=10)         # independent (not just uncorrelated) components
KernelPCA(kernel="rbf", n_components=2)   # non-linear PCA via kernel trick

t-SNE & manifold learners — 2-D visualization only

Intuition: place points in 2-D so that local neighborhoods are preserved. Beautiful for inspecting clusters; not a general feature reducer.

from sklearn.manifold import TSNE, Isomap, LocallyLinearEmbedding, MDS, SpectralEmbedding

ts = TSNE(
    n_components=2,
    perplexity=30,          # roughly: expected #neighbors per cluster (5–50)
    learning_rate="auto",
    init="pca",
    random_state=42,
).fit_transform(X_scaled)
three rules

1) Distances between clusters in a t-SNE plot are meaningless. 2) Cluster sizes are meaningless. 3) Never feed t-SNE output to a downstream model — it has no .transform() for new points.

Hyperparameter tuning

Models have two kinds of parameters: those learned from data (coef_, tree_, …) and those you set (C, max_depth, …). Tuning the second kind is what these tools do.

GridSearchCV — exhaustive

from sklearn.model_selection import GridSearchCV

param_grid = {
    "n_estimators": [100, 300, 600],
    "max_depth":    [None, 10, 20],
    "min_samples_leaf": [1, 5, 20],
}
gs = GridSearchCV(
    estimator=RandomForestClassifier(random_state=42),
    param_grid=param_grid,
    cv=5,
    scoring="f1_macro",
    n_jobs=-1,
    refit=True,      # after CV, refit best params on full training data
    verbose=1,
).fit(X_tr, y_tr)

gs.best_params_, gs.best_score_, gs.best_estimator_
import pandas as pd
pd.DataFrame(gs.cv_results_).sort_values("rank_test_score").head()

RandomizedSearchCV — sample, don't enumerate

For more than ~3 hyperparameters, random search beats grid search at the same compute budget. (Famous result by Bergstra & Bengio.) Pass distributions instead of lists.

from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform, randint

param_dist = {
    "learning_rate": loguniform(1e-3, 1),     # continuous, log-spaced
    "max_iter":      randint(100, 1000),         # integer uniform
    "max_leaf_nodes": [15, 31, 63, 127],
    "l2_regularization": loguniform(1e-4, 1),
}
rs = RandomizedSearchCV(
    HistGradientBoostingClassifier(random_state=42),
    param_dist, n_iter=60, cv=5, scoring="f1_macro",
    n_jobs=-1, random_state=42,
).fit(X_tr, y_tr)

HalvingGridSearchCV — successive halving

Start with many configs on a small data subset, kill the bad ones each round, give survivors more data. Often 5–10× faster than grid search at similar quality.

from sklearn.experimental import enable_halving_search_cv   # required
from sklearn.model_selection import HalvingRandomSearchCV
hs = HalvingRandomSearchCV(estimator, param_dist, factor=3, random_state=42).fit(X_tr, y_tr)

Learning & validation curves — diagnose first, tune second

from sklearn.model_selection import learning_curve, validation_curve

# Are we under-fitting or over-fitting?
sizes, train_sc, val_sc = learning_curve(
    model, X, y, cv=5,
    train_sizes=np.linspace(0.1, 1.0, 10),
    scoring="f1_macro", n_jobs=-1,
)

# How does score change with one hyperparameter?
train_sc, val_sc = validation_curve(
    model, X, y,
    param_name="max_depth", param_range=[2,4,8,16,32],
    cv=5, scoring="f1_macro",
)
read the curves

Train and val both low and close → underfit (model too simple). Train high, val much lower → overfit. Both high and close → done. Gap closes as you add data → more data will help; flat → it won't.

11

Pipelines & ColumnTransformer

The single most underused tool in sklearn. A Pipeline turns "preprocess + model" into one object that does the right thing inside cross-validation, can be grid-searched end-to-end, and can be saved to disk as one artifact.

Why pipelines exist

Manual — leaks & bugs

Fit a scaler on full X, split, fit a model. The CV scores are now biased because the scaler saw the validation rows. Plus your "deploy" code has to remember every step in the same order.

Pipeline — correct & clean

Each CV fold fits the scaler on that fold's train rows only. One object holds preprocessing + model. Save it, load it, predict — done.

A complete real-world pipeline

from sklearn.pipeline       import Pipeline
from sklearn.compose        import ColumnTransformer, make_column_selector
from sklearn.preprocessing  import StandardScaler, OneHotEncoder
from sklearn.impute         import SimpleImputer
from sklearn.ensemble       import HistGradientBoostingClassifier

num_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median", add_indicator=True)),
    ("scale",  StandardScaler()),
])
cat_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("ohe",    OneHotEncoder(handle_unknown="ignore", min_frequency=10, sparse_output=False)),
])

# Auto-pick columns by dtype — no hard-coded column lists
pre = ColumnTransformer([
    ("num", num_pipe, make_column_selector(dtype_include="number")),
    ("cat", cat_pipe, make_column_selector(dtype_include="object")),
], remainder="drop", verbose_feature_names_out=False)

clf = Pipeline([
    ("pre",   pre),
    ("model", HistGradientBoostingClassifier(random_state=42)),
])

clf.fit(X_tr, y_tr)
clf.score(X_te, y_te)
clf.predict_proba(X_te)

Tuning preprocessing & model together

Pipelines name their steps. To address a step's hyperparameter use step__param. To address a nested step: step__substep__param.

grid = {
    "pre__num__impute__strategy":    ["median", "mean"],
    "pre__cat__ohe__min_frequency":   [5, 10, 50],
    "model__learning_rate":           [0.05, 0.1, 0.2],
    "model__max_leaf_nodes":          [31, 63, 127],
}
gs = GridSearchCV(clf, grid, cv=5, scoring="f1_macro", n_jobs=-1).fit(X_tr, y_tr)

FeatureUnion — parallel transformers, concatenated

ColumnTransformer routes different columns to different transformers. FeatureUnion runs several transformers on the same data and concatenates their outputs (e.g. PCA features alongside raw scaled features).

from sklearn.pipeline import FeatureUnion
from sklearn.decomposition import PCA
combined = FeatureUnion([("raw", StandardScaler()), ("pca", PCA(n_components=5))])

Feature selection

Three reasons to drop features: speed (fewer columns = faster), generalization (less noise to memorize), and interpretability (fewer things to explain). Four families of selectors:

1 · Filter — score features individually

from sklearn.feature_selection import (
    VarianceThreshold,
    SelectKBest, SelectPercentile,
    f_classif, mutual_info_classif, chi2,
)
# Drop near-constant features
VarianceThreshold(threshold=0.01).fit_transform(X)

# Top-K by ANOVA F-test (linear) or mutual info (non-linear)
SelectKBest(score_func=mutual_info_classif, k=30).fit_transform(X, y)

2 · Wrapper — score by retraining the model

from sklearn.feature_selection import RFE, RFECV, SequentialFeatureSelector

# Recursive feature elimination — fit, drop weakest, repeat
rfe = RFE(estimator=LogisticRegression(), n_features_to_select=20, step=1)

# With CV — auto-pick the optimal feature count
rfecv = RFECV(estimator=LogisticRegression(), cv=5, scoring="f1_macro")

# Forward / backward greedy
sfs = SequentialFeatureSelector(LogisticRegression(), n_features_to_select=15, direction="forward")

3 · Embedded — model picks during training

from sklearn.feature_selection import SelectFromModel
from sklearn.linear_model     import LassoCV
from sklearn.ensemble         import RandomForestClassifier

# Use Lasso's non-zero coefficients
sfm = SelectFromModel(estimator=LassoCV(), threshold="median").fit(X, y)

# Or a forest's importances
sfm = SelectFromModel(estimator=RandomForestClassifier(), threshold="1.25*mean").fit(X, y)

4 · Permutation importance — what to drop based on what hurts when removed

(Lives in sklearn.inspection, covered in next chapter.) The most trustworthy importance signal, because it's defined by behaviour rather than internal model details.

Model inspection & interpretation

A black box that scores well isn't trustworthy yet. Inspection tools tell you why the model predicts what it predicts.

Permutation importance

Idea: after fitting, shuffle one feature's values and see how much performance drops. Big drop = important feature. Model-agnostic, more reliable than .feature_importances_.

from sklearn.inspection import permutation_importance
r = permutation_importance(
    model, X_te, y_te,
    n_repeats=10,
    scoring="f1_macro",
    random_state=42,
    n_jobs=-1,
)
import pandas as pd
pd.Series(r.importances_mean, index=feature_names).sort_values()
correlated features

Permutation importance can split credit oddly across correlated features. If two features carry the same signal, shuffling either one alone barely hurts — so both look unimportant. Cluster correlated features and permute together, or look at SHAP for that case.

Partial dependence & ICE plots

Shows the average predicted outcome as a function of one (or two) features. Essential for explaining models to stakeholders.

from sklearn.inspection import PartialDependenceDisplay, partial_dependence

PartialDependenceDisplay.from_estimator(
    model, X_te,
    features=["age", "income", ("age", "income")],   # tuple = 2-D interaction
    kind="both",        # "average" (PD) + "individual" (ICE)
)

Inspecting linear coefficients

import pandas as pd

# coefficient magnitude is a clean importance score.

Text vectorization

Before any model can see text, you turn strings into numeric vectors. sklearn ships three classic vectorizers; for modern embeddings you'd pair sklearn with a transformer model.

CountVectorizer — bag of words

from sklearn.feature_extraction.text import CountVectorizer
cv = CountVectorizer(
    lowercase=True,
    ngram_range=(1, 2),       # unigrams + bigrams
    min_df=5,                  # ignore terms in < 5 docs
    max_df=0.9,                # ignore terms in > 90% of docs (stopwords-ish)
    stop_words="english",
    max_features=50000,

X = cv.fit_transform(docs)         # sparse matrix
cv.get_feature_names_out()

TfidfVectorizer — weighted by inverse doc frequency

Down-weights words that appear everywhere ("the"). Usually beats raw counts for classification.

from sklearn.feature_extraction.text import TfidfVectorizer
tf = TfidfVectorizer(ngram_range=(1, 2), min_df=5, sublinear_tf=True)
X = tf.fit_transform(docs)

HashingVectorizer — streaming & stateless

No vocabulary to learn — uses the hash of each token as the feature index. Works with partial_fit models for online learning on huge text streams.

from sklearn.feature_extraction.text import HashingVectorizer

Anomaly & outlier detection

Two related problems: outlier detection (find the weird rows in the data you already have) and novelty detection (flag weird rows arriving later, after fitting on clean data). All four estimators below expose a .predict() that returns +1 (inlier) or −1 (outlier).

IsolationForest — the workhorse

Intuition: outliers are easier to isolate via random partitions than normal points. Fast, handles high dimensions, almost zero tuning.

from sklearn.ensemble import IsolationForest
iso = IsolationForest(
    n_estimators=200,
    contamination="auto",   # or a float like 0.05 for "5% are anomalies"
    random_state=42,
    n_jobs=-1,
).fit(X)
y_out = iso.predict(X)            # +1 inlier, -1 outlier
scores = iso.score_samples(X)     # lower = more anomalous

LocalOutlierFactor — density-based

Compares each point's local density to its neighbors. Great when anomalies are locally sparse but globally normal.

from sklearn.neighbors import LocalOutlierFactor
lof = LocalOutlierFactor(n_neighbors=20, contamination=0.05, novelty=False)
y_out = lof.fit_predict(X)
# novelty=True if you want to fit on clean data and predict() new data

OneClassSVM — boundary around normal data

from sklearn.svm import OneClassSVM
oc = OneClassSVM(kernel="rbf", gamma="scale", nu=0.05).fit(X_clean)

EllipticEnvelope — Gaussian boundary

Assumes inliers are Gaussian. Cheap and good when that assumption roughly holds.

from sklearn.covariance import EllipticEnvelope
EllipticEnvelope(contamination=0.05).fit(X_clean)

Calibration, imbalance, persistence

Three production-grade topics most tutorials skip but that you'll hit on day one of real work.

Probability calibration

Many classifiers (SVMs, Naive Bayes, tree ensembles) output scores that look like probabilities but aren't. A model that says "0.9 confidence" might be right 70% of the time. Calibration fixes this.

from sklearn.calibration import CalibratedClassifierCV, calibration_curve

# Two methods: isotonic (non-parametric, needs ≥ 1k samples) or sigmoid (Platt scaling)
cal = CalibratedClassifierCV(base_model, method="isotonic", cv=5).fit(X_tr, y_tr)

# Diagnose with a reliability curve
prob_true, prob_pred = calibration_curve(y_te, cal.predict_proba(X_te)[:, 1], n_bins=10)

Class imbalance — the toolbox

When one class is 1% and another is 99%, accuracy is useless and most models lazily predict the majority class.

  1. Pick the right metric — F1, PR-AUC, MCC. Not accuracy.
  2. Use class_weight="balanced" on the estimator. Many sklearn models support this for free.
  3. Use stratify=y on the split and StratifiedKFold for CV.
  4. Resample inside the pipeline with imbalanced-learn's SMOTE or RandomUnderSampler — never before the split.
  5. Tune the threshold. predict() hard-codes 0.5; manually pick a threshold that optimizes your real metric.
# Move the threshold to optimize F1
from sklearn.metrics import precision_recall_curve
prob = model.predict_proba(X_te)[:, 1]
p, r, t = precision_recall_curve(y_te, prob)
f1 = 2*p*r / (p + r + 1e-12)
best_t = t[f1[:-1].argmax()]
y_pred = (prob >= best_t).astype(int)

Saving and loading models

import joblib
joblib.dump(pipeline, "model.joblib", compress=3)
loaded = joblib.load("model.joblib")
loaded.predict(new_X)
version match

A pickled sklearn model is portable only across compatible sklearn versions. Pin scikit-learn==x.y.z in your serving environment, and store the version inside the artifact (or use skops for a safer serialization format).

Advanced: custom estimators & online learning

Two topics that move you from using sklearn to extending it.

Writing a custom transformer

Inherit from BaseEstimator and TransformerMixin. The mixin gives you fit_transform() for free; the base class makes the object grid-searchable and clone-able.

from sklearn.base import BaseEstimator, TransformerMixin
import numpy as np

class ClipOutliers(BaseEstimator, TransformerMixin):
    """Clip each feature to [q_low, q_high] quantiles learned from train."""
    def __init__(self, q_low=0.01, q_high=0.99):
        self.q_low = q_low
        self.q_high = q_high

    def fit(self, X, y=None):
        X = np.asarray(X)
        self.low_  = np.quantile(X, self.q_low,  axis=0)
        self.high_ = np.quantile(X, self.q_high, axis=0)
        return self

    def transform(self, X):
        return np.clip(X, self.low_, self.high_)

# Drop into any Pipeline — works with GridSearchCV, joblib, everything
pipe = Pipeline([("clip", ClipOutliers()), ("sc", StandardScaler()), ("m", LogisticRegression())])
three rules

1) All __init__ arguments must be stored verbatim on self. 2) Anything learned in fit must end with an underscore (low_, scale_). 3) fit must return self.

Online / incremental learning with partial_fit

For data that doesn't fit in memory, or that arrives in a stream. A subset of estimators support partial_fit(X_chunk, y_chunk, classes=...).

from sklearn.linear_model import SGDClassifier
import numpy as np

m = SGDClassifier(loss="log_loss", random_state=42)
classes = np.unique(y_full)        # MUST be passed every partial_fit call

for X_chunk, y_chunk in stream_batches():
    m.partial_fit(X_chunk, y_chunk, classes=classes)

Models that support partial_fit: SGDClassifier/Regressor, PassiveAggressive*, MultinomialNB, BernoulliNB, MiniBatchKMeans, MLPClassifier, IncrementalPCA.

Sample & class weights — push the loss around

# Per-sample weights, accepted by most fit() methods:
model.fit(X, y, sample_weight=w)

# Per-class weights (or "balanced" to auto-compute):
RandomForestClassifier(class_weight={0: 1, 1: 10})
LogisticRegression(class_weight="balanced")

Parallelism & reproducibility — production hygiene

m = RandomForestClassifier(
    n_estimators=500,
    n_jobs=-1,         # use every core
    random_state=42,   # reproducible runs
    warm_start=True,    # add trees on subsequent fits without restarting
)
m.fit(X, y)
m.n_estimators += 200
m.fit(X, y)            # trains the extra 200 only

How to actually study this

  1. Read chapters 1–4 once. Then build something tiny: load Iris, scale, split, fit a LogisticRegression, score. Don't move on until that workflow feels boring.
  2. Cycle through chapters 5–7. For each model: read the intuition, run it on make_classification, look at one hyperparameter via validation_curve. You're building a mental gallery of "which knob does what."
  3. Chapter 11 (Pipelines) is the unlock. Once you wrap every workflow in a Pipeline, you'll never go back. From here on, everything else slots into the pipeline as a step.
  4. Chapters 9–10 teach you to evaluate and improve rigorously. This is where most learners plateau — they pick a metric on autopilot and miss the real problem.
  5. Chapters 12–17 are where intermediate becomes advanced. You don't need them on day one, but you'll reach for them more than you'd expect.

The goal isn't to memorize APIs. It's to develop taste: knowing which tool to reach for, which gotcha to anticipate, and which baseline to beat.
