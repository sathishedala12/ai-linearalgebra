beyond scikit-learn · the AI/ML engineer's toolkit (2026)

Twenty libraries, one career.

The complete map of what an AI/ML Engineer actually uses day-to-day — grouped by the four pillars of the job, with an honest take on what matters now versus what's just noise.

Pillar 1

Wrangle the data

Load, clean, transform, visualize. 60% of the job lives here. NumPy, Pandas, Polars, viz tools.

Pillar 2

Model the problem

Classical ML, gradient boosting, deep learning. sklearn handles the easy half; the rest needs PyTorch, XGBoost, transformers.

Pillar 3

Ship to production

APIs, containers, monitoring. A model that lives in a notebook isn't a product. FastAPI, Docker, ONNX.

Pillar 4

Operate & iterate

Track experiments, version data, orchestrate retraining, detect drift. MLflow, W&B, Airflow, DVC.

Tiers — learn roughly in this order

01Data foundations (NumPy, Pandas, Polars, Viz) 02Tabular ML beyond sklearn (XGBoost, LightGBM, Optuna, SHAP) 03Deep learning (PyTorch, Lightning, JAX) 04LLMs & modern AI (Transformers, LangChain, Embeddings) 05Retrieval & vector search (FAISS, Chroma, pgvector) 06Serving & deployment (FastAPI, Docker, ONNX) 07MLOps (MLflow, W&B, Airflow, DVC) 08Specialized domains (NLP, CV, time series, big data)
01

Data foundations

non-negotiable

Every ML problem starts with messy data. You'll spend more time here than on modeling — and the bottleneck is rarely scikit-learn, it's pandas. Master these four first.

NumPy
★ 28k
N-dimensional arrays · the bedrock

The mathematical foundation under pandas, sklearn, PyTorch, and every other library here. Vectorized operations on arrays are 50–100× faster than Python loops.

Master: broadcasting, fancy indexing, axis-aware reductions, np.where, einsum.
import numpy as np
X = np.random.randn(1000, 20)         # 1000×20 matrix
mean = X.mean(axis=0)                  # per-column mean
Z = (X - mean) / X.std(axis=0)        # standardize — no loops
→ everything builds on this
Pandas
★ 44k
Tabular data, the universal currency

DataFrames for loading, cleaning, joining, grouping, reshaping data. If your data comes in CSV/Parquet/SQL/Excel/JSON, pandas reads it. The skill that separates juniors from seniors.

Master: groupby + agg, merge/join, pivot_table, melt, apply vs vectorized, .loc vs .iloc, MultiIndex.
import pandas as pd
df = pd.read_parquet("events.parquet")
(df.query("country == 'US'")
   .groupby(["segment", "month"])
   .agg(revenue=("amount", "sum"),
        users=("user_id", "nunique")))
→ next: Polars for speed
Polars
★ 29k · fast-growing
Pandas, rewritten in Rust

Same conceptual model as pandas but 5–30× faster, lower memory, with a lazy query optimizer. Increasingly the production choice for anything > 1 GB. The pandas API stays for analysis; Polars takes over for pipelines.

Reach for it when: pandas is slow, you're hitting memory limits, or you're building a recurring data pipeline.
import polars as pl
df = pl.scan_parquet("events.parquet")        # lazy
(df.filter(pl.col("country") == "US")
   .group_by(["segment", "month"])
   .agg(pl.col("amount").sum())
   .collect())                              # execute
→ familiar after pandas; learn in a weekend
Matplotlib + Seaborn + Plotly
visualization stack
Three plotting libraries, three jobs

Matplotlib is the low-level engine — verbose but total control. Seaborn is statistical plots in one line on top of matplotlib. Plotly is interactive plots for dashboards and notebooks.

Day-to-day: seaborn for EDA, matplotlib for paper-quality customization, plotly when stakeholders need to hover.
import seaborn as sns
sns.pairplot(df, hue="target")             # 1 line, 25 plots
sns.heatmap(df.corr(), annot=True)        # correlation matrix
→ skip altair / bokeh until you need them
02

Tabular ML beyond sklearn

expected on the job

For tabular data, sklearn's HistGradientBoosting is excellent but not state-of-the-art. The dedicated gradient boosting libraries below dominate Kaggle and most production tabular ML. Plus the trio of tools that wrap any model: tuning, explaining, balancing.

XGBoost
★ 26k
Gradient boosting, battle-tested

The gradient-boosted tree library that started the modern tabular ML era. Still the most-used model in industry for structured data. Handles missing values natively, has GPU support, and exposes hundreds of knobs.

Reach for it when: tabular problem, accuracy matters, ≤ ~10M rows. Beats sklearn's HistGradientBoosting by 1–3% typically.
import xgboost as xgb
m = xgb.XGBClassifier(
    n_estimators=500, learning_rate=0.05,
    max_depth=6, subsample=0.8,
    tree_method="hist", device="cuda",
    early_stopping_rounds=50,
).fit(X_tr, y_tr, eval_set=[(X_val, y_val)])
→ partners with: Optuna, SHAP
LightGBM
★ 17k
XGBoost's faster cousin

From Microsoft. Often 2–10× faster than XGBoost with similar accuracy; uses leaf-wise tree growth and exclusive feature bundling. The Kaggle winner most of the time now.

Reach for it when: very large tabular data, or you need fast iteration. Slightly more prone to overfit on small data.
import lightgbm as lgb
m = lgb.LGBMClassifier(
    n_estimators=1000, learning_rate=0.05,
    num_leaves=63, feature_fraction=0.8,
).fit(X_tr, y_tr,
      eval_set=[(X_val, y_val)],
      callbacks=[lgb.early_stopping(50)])
→ same API as XGBoost; learn one, get the other for free
CatBoost
★ 8k
Gradient boosting that loves categoricals

From Yandex. Built-in handling of categorical features without manual encoding — uses a clever ordered target encoding that avoids leakage. Often wins on data with lots of high-cardinality categoricals.

Reach for it when: many string/categorical columns, or you don't want to fuss with encoding pipelines.
from catboost import CatBoostClassifier
m = CatBoostClassifier(
    iterations=1000, learning_rate=0.05,
    cat_features=["country", "plan", "campaign"],
    verbose=100,
).fit(X_tr, y_tr, eval_set=(X_val, y_val))
→ pick one of XGB / LGBM / Cat — learn all three eventually
Optuna
★ 11k
Hyperparameter optimization done right

Smarter than GridSearchCV or RandomizedSearchCV. Uses Bayesian optimization (Tree Parzen Estimator) to learn which hyperparameter regions are promising and focus search there. Comes with pruning, parallelism, and a slick dashboard.

Replace: sklearn's grid/random search for any non-trivial tuning problem.
import optuna

def objective(trial):
    params = {
      "learning_rate": trial.suggest_float("lr", 1e-3, 0.3, log=True),
      "max_depth":     trial.suggest_int("d", 3, 12),
    }
    return cv_score(params)

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=100)
→ pairs with literally every model
SHAP
★ 23k
Explaining any model's predictions

Game-theoretic feature attribution. For every prediction, tells you how much each feature pushed the output up or down. The standard for model interpretability — required for regulated industries (finance, healthcare, hiring).

Use for: debugging a model's mistakes, explaining decisions to stakeholders, audit and compliance.
import shap
explainer = shap.TreeExplainer(model)
shap_values = explainer(X_test)

shap.summary_plot(shap_values, X_test)     # global importance
shap.waterfall_plot(shap_values[0])       # single-prediction breakdown
→ alternative: LIME (older, less popular now)
imbalanced-learn
★ 7k
SMOTE and friends, sklearn-compatible

Class imbalance toolbox. Drops into sklearn pipelines via its own Pipeline (the sklearn one won't resample inside CV correctly). SMOTE, ADASYN, undersamplers, combinations.

Reach for it when: minority class < 10%, especially with critical false-negative cost (fraud, churn, medical).
from imblearn.over_sampling import SMOTE
from imblearn.pipeline      import Pipeline

pipe = Pipeline([
    ("smote", SMOTE(random_state=42)),
    ("clf",   XGBClassifier()),
]).fit(X_tr, y_tr)                       # SMOTE runs ONLY on train folds
→ also try: class_weight, threshold tuning
03

Deep learning

core competency

When data is images, audio, text, or large & complex tabular — neural networks beat classical ML. PyTorch is the default now, even at Google. Learn it deeply; the rest is variations.

PyTorch
★ 84k · the standard
The deep learning framework that won

Dynamic computation graphs, Python-native, and the framework virtually every modern model is written in (GPT, Llama, Stable Diffusion, AlphaFold). If you learn one DL library, learn this one. The ecosystem (TorchVision, TorchAudio, TorchText, PyTorch Geometric) covers vision, audio, text, graphs.

Master: tensors & autograd, nn.Module classes, DataLoader, training loops, GPU placement, mixed precision, distributed training.
import torch
import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, in_dim, hidden, out_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, out_dim),
        )
    def forward(self, x): return self.net(x)

model = MLP(20, 128, 3).cuda()
opt   = torch.optim.AdamW(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()

for X, y in loader:
    X, y = X.cuda(), y.cuda()
    opt.zero_grad()
    loss = loss_fn(model(X), y)
    loss.backward()
    opt.step()
→ next: Lightning for boilerplate, Hugging Face for pretrained models
PyTorch Lightning
★ 28k
PyTorch without the boilerplate

Wraps your model + training step in a class; Lightning handles the training loop, multi-GPU, checkpointing, logging, mixed precision. Same flexibility as raw PyTorch, half the code.

Use it when: training loop is more than ~30 lines, you want multi-GPU/multi-node training without writing distributed code.
import lightning as L

class LitMLP(L.LightningModule):
    def training_step(self, batch, _):
        X, y = batch
        loss = F.cross_entropy(self(X), y)
        self.log("loss", loss)
        return loss

trainer = L.Trainer(max_epochs=20, accelerator="gpu", devices=4)
trainer.fit(LitMLP(), train_loader, val_loader)
→ alternative: bare PyTorch + your own helpers
TensorFlow / Keras
★ 186k · legacy-heavy
Google's framework — still in enterprise

Was the dominant framework, now second to PyTorch. Keras 3 is multi-backend (TF, JAX, PyTorch) and a clean API for beginners. Worth knowing because many enterprise codebases use it, and TFLite still dominates on-device inference.

Learn it when: your team already uses it, or you target mobile/edge inference (TFLite, TF.js).
import keras
model = keras.Sequential([
    keras.layers.Dense(128, activation="relu"),
    keras.layers.Dense(3, activation="softmax"),
])
model.compile(optimizer="adam", loss="sparse_categorical_crossentropy")
model.fit(X, y, epochs=10)
→ if starting fresh in 2026, prefer PyTorch
JAX
★ 31k · research-favorite
NumPy + autograd + XLA compilation

From Google. Feels like NumPy but with automatic differentiation and just-in-time compilation to GPU/TPU. The research framework of choice at DeepMind, Anthropic, and many top labs. Steeper learning curve; pure functional style.

Learn it if: you want to do ML research, custom optimization, or use TPUs at scale. Otherwise skip until needed.
import jax, jax.numpy as jnp
from jax import grad, jit

def loss(w, X, y): return jnp.mean((X @ w - y) ** 2)

grad_fn = jit(grad(loss))               # compiled gradient — fast
w = w - 0.01 * grad_fn(w, X, y)
→ ecosystem: Flax (modules), Optax (optimizers)
04

LLMs & modern AI

defines the 2026 role

This is the section that didn't exist five years ago and is now half the AI/ML Engineer job. You don't train foundation models — you apply, fine-tune, and orchestrate them. Get fluent here.

Hugging Face Transformers
★ 145k · the hub
Every pretrained model, one API

The library that made modern NLP/CV/audio accessible. Thousands of pretrained models (BERT, Llama, Whisper, ViT, CLIP, SD) — download, fine-tune, or just run inference with three lines. Comes with companion libraries: datasets, tokenizers, accelerate, peft (LoRA/QLoRA), trl (RLHF/DPO).

Master: pipeline() for prototyping, AutoModel/AutoTokenizer for control, Trainer for fine-tuning, peft for parameter-efficient tuning.
from transformers import pipeline, AutoModelForSequenceClassification, AutoTokenizer

# Zero to inference in 3 lines
clf = pipeline("sentiment-analysis", model="distilbert-base-uncased-finetuned-sst-2-english")
clf(["This product saved my project.", "Slow and buggy."])

# Or load and fine-tune
tok  = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModelForSequenceClassification.from_pretrained("bert-base-uncased", num_labels=3)
→ surrounding tools: datasets, peft, accelerate, trl
LangChain / LlamaIndex
★ 90k + ★ 33k
Building applications on top of LLMs

Frameworks for chaining LLM calls into useful applications: RAG (retrieval-augmented generation), agents, tool use, multi-step reasoning. LangChain is broader and more flexible; LlamaIndex is laser-focused on retrieval/RAG.

Reach for it when: building chat-with-your-docs, agent workflows, or LLM apps with structured outputs. Be aware: APIs change often.
from langchain.chat_models import ChatAnthropic
from langchain.prompts     import ChatPromptTemplate

llm = ChatAnthropic(model="claude-opus-4-7")
prompt = ChatPromptTemplate.from_template("Summarize: {text}")
chain = prompt | llm
chain.invoke({"text": doc})
→ alternatives: raw API + your own glue (often cleaner)
Sentence-Transformers
★ 15k
Embeddings, the gateway to semantic search

Turn text (or images) into dense vectors that capture meaning. Two paragraphs about the same topic land near each other in vector space. The foundation under RAG, semantic search, clustering of documents, recommendation.

Use it when: you need to compare texts by meaning, build search, or feed a vector DB. Faster & cheaper than calling an LLM API per text.
from sentence_transformers import SentenceTransformer
model = SentenceTransformer("all-MiniLM-L6-v2")

emb = model.encode([
    "How do I cancel my subscription?",
    "Where do I update billing?",
])                                  # shape (2, 384)
# Cosine similarity → these two are close
→ next: feed into FAISS / Chroma / pgvector
OpenAI / Anthropic SDKs
official clients
Foundation model APIs, directly

The thinnest, most reliable way to call GPT-4, Claude, Gemini. Honestly, for most LLM apps, the SDK + a few helper functions beats any heavy framework. Both support tool use, streaming, vision, structured outputs.

Default for: production LLM features where you control the prompts. Reach for LangChain only when orchestration genuinely helps.
from anthropic import Anthropic
client = Anthropic()

resp = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Explain RAG in one paragraph."}],
)
print(resp.content[0].text)
→ unify many providers: LiteLLM
DSPy
★ 19k · rising
Programming LLMs, not prompting them

From Stanford. Replace hand-tuned prompt strings with composable modules that get compiled (auto-prompt-optimized) against your task. The next layer of abstraction over raw prompting. Worth learning early.

Reach for it when: building multi-step LLM pipelines and you want repeatable quality without endless prompt tweaking.
import dspy
classify = dspy.Predict("text -> sentiment, confidence")
result = classify(text="This is amazing!")
print(result.sentiment, result.confidence)
→ still volatile; watch the field
vLLM / Ollama
serving + local
Running open-source LLMs yourself

vLLM is the production serving engine for open models (Llama, Mistral, Qwen) — 10–20× faster throughput than naive transformers inference. Ollama is the dev-friendly way to run models locally with one command.

Reach for them when: cost / data privacy rules out cloud APIs, or you need self-hosted inference at scale.
# Ollama — one command per model
# $ ollama run llama3.1:70b

# vLLM — production serving
from vllm import LLM, SamplingParams
llm = LLM(model="meta-llama/Llama-3.1-8B-Instruct")
out = llm.generate(["What is RAG?"], SamplingParams(temperature=0.7))
→ alternatives: TGI, SGLang, llama.cpp
05

Retrieval & vector search

RAG enabler

RAG (retrieval-augmented generation) made vector databases ubiquitous. You embed documents, store the vectors, and retrieve relevant chunks to feed an LLM. Learn one in-memory option and one persistent option.

FAISS
★ 33k
In-memory vector search, no DB

From Meta. Pure library — give it a numpy array of embeddings, it builds an index and answers nearest-neighbor queries in milliseconds. No server, no schema. Perfect for prototypes and small-to-medium corpora.

import faiss
index = faiss.IndexFlatIP(384)         # cosine via inner product
index.add(embeddings)
D, I = index.search(query_emb, k=5)
→ fast, but no persistence built-in
Chroma / Qdrant
popular vector DBs
Persistent, filterable, production-ready

Chroma is the simplest — drop-in, embedded, perfect for getting started. Qdrant is more production-grade with rich filtering, payload storage, and horizontal scaling. Both speak the same conceptual API.

import chromadb
client = chromadb.Client()
col = client.create_collection("docs")
col.add(documents=["..."], ids=["d1"])
col.query(query_texts=["how to..."], n_results=3)
→ alternatives: Pinecone, Weaviate, Milvus
pgvector
PostgreSQL extension
Vector search in your existing database

If you already use Postgres, you might not need a separate vector DB. Adds vector columns, similarity operators, and ANN indexes (HNSW, IVFFlat). Lets you filter by SQL columns and similarity in one query — huge for production apps.

# SQL — yes, really
# SELECT id, content
# FROM docs
# WHERE tenant_id = $1
# ORDER BY embedding <=> $2
# LIMIT 5;
→ favorite of teams who don't want infra sprawl
06

Serving & deployment

production readiness

A model that lives in a notebook isn't a product. The handoff from train to serve is what separates research from engineering. These tools turn a pickle file into a service.

FastAPI
★ 80k
The default Python API framework

Async, type-hinted, auto-generates OpenAPI docs, and 5–10× faster than Flask. Wraps a model into an HTTP service in ~15 lines. Knowing FastAPI is table stakes for any ML role that touches deployment.

from fastapi import FastAPI
from pydantic import BaseModel
import joblib

model = joblib.load("model.joblib")
app = FastAPI()

class Input(BaseModel):
    features: list[float]

@app.post("/predict")
def predict(req: Input):
    p = model.predict_proba([req.features])[0]
    return {"prob": p.tolist()}
→ run with uvicorn or gunicorn+uvicorn
Docker
infrastructure baseline
Containers — your model + its world

Not Python. Not optional. Every ML model goes into a container before it goes to production. Docker freezes your Python version, package versions, and OS into a portable image. Required for Kubernetes, every cloud, every CI/CD pipeline.

# Dockerfile
FROM python:3.11-slim
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . /app
WORKDIR /app
CMD ["uvicorn", "main:app", "--host", "0.0.0.0"]
→ next step: Kubernetes (only when scale demands it)
ONNX
interchange format
Run any model anywhere

A neutral graph format. Convert sklearn / PyTorch / TF models into .onnx files, then run them via ONNX Runtime — often faster than the source framework, on CPU, GPU, mobile, or browser (via onnxruntime-web).

import torch.onnx
torch.onnx.export(model, dummy, "model.onnx")

import onnxruntime as ort
sess = ort.InferenceSession("model.onnx")
out  = sess.run(None, {"input": arr})
→ huge for edge / browser deployment
Gradio / Streamlit
demo UIs
A web UI for your model in 20 lines

Both let you build a working web demo without touching HTML/CSS/JS. Gradio is loved for ML demos (especially HF Spaces). Streamlit is broader, better for data dashboards. Not for production user-facing apps, but unbeatable for stakeholder demos and internal tools.

import gradio as gr
def classify(text):
    return model(text)[0]

gr.Interface(fn=classify, inputs="text", outputs="label").launch()
→ replaces: 90% of "I need a quick UI" needs
07

MLOps — track, version, orchestrate

senior-level differentiator

Once you train more than three models, you'll forget which one was best. Once you have data flowing daily, you'll need orchestration. The tools below answer "which experiment? which dataset? which pipeline run?" — the questions that separate a script from a system.

MLflow
★ 19k · open source
Experiment tracking + model registry

Log metrics, params, artifacts of every training run; compare them in a UI; promote the best to a registry; serve from the registry. Self-hostable, framework-agnostic, free.

import mlflow
with mlflow.start_run():
    mlflow.log_params({"lr": 0.05, "depth": 6})
    mlflow.log_metrics({"f1": 0.87, "auc": 0.93})
    mlflow.sklearn.log_model(model, "clf")
→ alternative: Weights & Biases (hosted, slicker UI)
Weights & Biases
SaaS standard
Experiment tracking, but prettier

Hosted version of MLflow with a much better UI: dashboards, sweeps (hyperparameter search), reports, artifacts, model registry, dataset versioning. Free for individuals/research; paid for teams.

import wandb
wandb.init(project="churn", config=params)
for epoch in range(20):
    train_loss = train()
    wandb.log({"loss": train_loss, "epoch": epoch})
→ pick W&B for solo work, MLflow if self-hosted is mandatory
DVC
data version control
Git for datasets and model files

Git can't handle 5 GB CSVs. DVC tracks data and model files via tiny pointer files in your git repo; the actual blobs live in S3/GCS/Azure. You can git-checkout a commit and get the matching data version. Critical for reproducibility.

# Add a dataset to versioning
# $ dvc add data/raw.parquet
# $ git add data/raw.parquet.dvc
# $ dvc push                      # uploads to S3
→ alternative: LakeFS, Pachyderm
Airflow / Prefect / Dagster
orchestrators
Pipelines, schedules, retries, alerts

When you have daily data flowing through preprocessing → training → evaluation → deployment, you need an orchestrator. Airflow is the legacy standard. Prefect is modern and Pythonic. Dagster is the data-asset-aware newcomer.

from prefect import flow, task

@task
def load(): return pd.read_parquet(...)

@task
def train(df): return model.fit(df)

@flow
def daily():
    df = load()
    m  = train(df)
→ pick one — they all solve the same problem
08

Specialized domains

learn what you'll touch

You don't need all of these. Pick by the domain you work in: text, images, time, big data. Each is the dominant tool in its niche.

spaCy
NLP
Production NLP pipelines

Industrial-grade tokenization, POS tagging, NER, dependency parsing. Faster than NLTK, with pretrained models in 70+ languages. Use it for structured information extraction from text; pair with transformers for state-of-the-art accuracy.

→ alternatives: NLTK (academic), Stanza
OpenCV + Pillow + timm
Vision
The image processing stack

OpenCV for classical CV (filtering, contours, transforms). Pillow for I/O and simple operations. timm (PyTorch Image Models) for 1000+ pretrained vision models — drop-in replacement for torchvision with better selection.

→ also: albumentations (augmentations)
statsmodels + Prophet + sktime
Time series
Forecasting toolbox

statsmodels for classical (ARIMA, SARIMAX, exponential smoothing) and statistical rigor (p-values, confidence intervals). Prophet for hands-off business forecasts with holidays. sktime brings the sklearn API to time-series tasks.

→ modern: NeuralForecast, Chronos
PySpark / Dask
Big data
When data won't fit in RAM

PySpark dominates in enterprises with Hadoop/Databricks ecosystems. Dask is the Pythonic "scale-out pandas" that feels more native. For most teams < 100 GB, Polars on a beefy box beats both.

→ also: Ray for distributed Python
NetworkX
Graphs
Graph algorithms in pure Python

Build, analyze, visualize networks. PageRank, shortest paths, community detection, centrality. For ML on graphs (GNNs), pair with PyTorch Geometric or DGL.

→ scale-up: graph-tool, cuGraph
Ray
distributed Python
Scale anything Python across a cluster

Distributed actor framework. Use cases: Ray Tune for distributed hyperparameter search, Ray Serve for model serving, Ray Data for ML preprocessing at scale, RLlib for reinforcement learning.

→ learn once, use across the stack

The 90-day roadmap

A realistic order for someone who already knows Python and sklearn. Treat it as a sequence of capability unlocks — by the end of each month you can do real work in a new area.

Weeks 1–3 · Foundations

Become unstoppable at data

  • NumPy: broadcasting, axis tricks
  • Pandas: groupby, merge, reshape
  • Polars: same patterns, lazy mode
  • Seaborn + Matplotlib for EDA
  • Project: end-to-end EDA on a Kaggle dataset
Weeks 4–6 · Tabular mastery

Beat sklearn's defaults

  • XGBoost + LightGBM (pick one to know deeply)
  • Optuna for tuning
  • SHAP for explanations
  • imbalanced-learn for skewed classes
  • Project: Kaggle tabular competition top 25%
Weeks 7–9 · Deep learning

PyTorch from scratch

  • Tensors, autograd, nn.Module
  • Build an MLP, a CNN, a small transformer
  • PyTorch Lightning for the boilerplate
  • torchvision/timm pretrained models
  • Project: fine-tune a vision model on custom data
Weeks 10–12 · Modern AI

Build with LLMs

  • Hugging Face Transformers + datasets
  • Sentence-Transformers + Chroma → RAG
  • Anthropic/OpenAI SDK + tool use
  • FastAPI to serve a model
  • Project: chat-with-your-docs deployed via Docker
depth over breadth

You don't need to know every library on this page. Pick one per tier and go deep. A senior who knows pandas, PyTorch, transformers, and FastAPI cold beats a junior with a tab open for everything.

build, don't bookmark

Every library here has a 10-minute "hello world" in its docs. Do them. Then build something real — a project teaches more than a month of tutorials. Aim for one shippable thing per tier.

follow the work

Your current job lives somewhere on this map. If you're doing CRM/marketing analytics, master pandas + xgboost + SHAP + FastAPI first. If you're doing chat features, master transformers + LangChain + vector DBs. Don't learn what's trendy; learn what unblocks tomorrow.
