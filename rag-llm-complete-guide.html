Chapter 01

LLM Fundamentals

Plain English Analogy

An LLM is a student who read the entire internet, then took an exam with the book closed. It knows a lot — but its knowledge is frozen at the exam date, and it can only answer from memory. RAG gives it an open-book.

1.1 What is an LLM?

Architecture

Transformer-based neural network. Self-attention heads learn relationships between tokens across long sequences.

Training

Pre-trained on billions of text tokens via next-token prediction (causal LM). Then fine-tuned with RLHF for helpfulness.

Inference

Given a prompt, the model generates tokens auto-regressively — each new token is conditioned on everything before it.

1.2 Key Concepts You Must Know

ConceptWhat It Means
Context WindowMax tokens the model sees at once. GPT-4: 128k, Gemini 1.5: 1M, Claude: 200k.
TemperatureRandomness of output. 0 = deterministic, 1+ = creative/random.
Top-P / Top-KSampling strategies that control token selection diversity.
HallucinationModel confidently states false info. A core problem RAG solves.
System PromptHidden instruction that sets role, tone, and constraints.
TokenRoughly ~4 chars. "PayPal" = 2 tokens. GPT-4 costs per 1k tokens.
Latent SpaceHigh-dimensional space where meaning is encoded numerically.

LLM FORWARD PASS (simplified) Input: "What is PayPal's refund policy?" 1. Tokenize → ["What", " is", " Pay", "Pal", "'s", " refund", ...] 2. Embed tokens → each token → 768-dim vector 3. Transformer blocks (×N layers) → self-attention across all tokens → feed-forward layers → layer norm 4. Output logits → probability over 50k vocab tokens 5. Sample next token → "PayPal" | "The" | "Refunds" ... → repeat until [EOS] token

1.4 LLM Limitations (Why RAG Exists)

🧊 Stale Knowledge

Training data has a cutoff. Cannot answer about events after that date.

🎭 Hallucination

Generates plausible-sounding but factually wrong answers with full confidence.

🔒 No Private Data

Knows nothing about your company docs, internal systems, or proprietary databases.

Chapter 02

Embeddings — Meaning as Numbers

Plain English Analogy

An embedding converts text into coordinates on a map. Similar texts live close together. "Dog" and "puppy" are neighbors. "Dog" and "refund policy" are far apart. Vector search finds the closest neighbors to your question.

2.1 What is an Embedding?

Definition

A dense numerical vector (list of floats) that captures semantic meaning. Two texts with similar meaning produce vectors that are close in high-dimensional space.

  • text-embedding-3-small: 1536 dimensions
  • sentence-transformers: 384–768 dims
  • Cohere embed-v3: 1024 dims
Embedding Example "PayPal refund takes 3 days" → embed → [0.12, -0.87, 0.43, 0.91, ...] (1536 floats) "How long does a PayPal dispute take?" → embed → [0.11, -0.84, 0.45, 0.89, ...] (nearby! cosine sim ≈ 0.94) "Best pizza in Fort Worth" → embed → [0.72, 0.31, -0.52, 0.04, ...] (far away — cosine sim ≈ 0.07)

2.2 Similarity Metrics

MetricFormulaRangeBest When
Cosine Similaritycos(θ) = A·B / (|A||B|)-1 to 1Most common — direction matters, not magnitude
Dot ProductA · B = Σ aᵢbᵢ-∞ to ∞When vectors are normalized (equals cosine)
Euclidean (L2)√Σ(aᵢ-bᵢ)²0 to ∞When absolute position matters
Manhattan (L1)Σ|aᵢ-bᵢ|0 to ∞Sparse vectors, outlier-robust

Chapter 03

Vector Databases

Plain English Analogy

A vector database is like a library that doesn't organize books alphabetically — it organizes them by vibe. Ask "give me something similar to Harry Potter" and it returns all the fantasy adventure books nearby, even if they have completely different titles.

3.1 How ANN Search Works

APPROXIMATE NEAREST NEIGHBOR (ANN) Brute force O(n·d) too slow at millions of vectors ANN trades tiny accuracy loss for massive speed gain HNSW (Hierarchical Navigable Small World) ← most popular → builds a graph of vectors at multiple zoom levels → navigates from coarse layer to fine layer to find neighbors → O(log n) query time Pinecone, Weaviate, Qdrant use this IVF (Inverted File Index) → clusters vectors with k-means, searches only relevant clusters → good for very large datasets (1B+ vectors) LSH (Locality Sensitive Hashing) → hashes similar vectors to same bucket → fast but lower recall

3.4 Code — Pinecone (Production)

python · pineconefrom pinecone import Pinecone, ServerlessSpec
from openai import OpenAI

pc = Pinecone(api_key="YOUR_KEY")
openai_client = OpenAI()

# Create index (1536 dims for text-embedding-3-small)
pc.create_index(
    name="paypal-knowledge",
    dimension=1536,
    metric="cosine",
    spec=ServerlessSpec(cloud="aws", region="us-east-1")
)
index = pc.Index("paypal-knowledge")

# Embed and upsert
def embed(text):
    return openai_client.embeddings.create(
        input=text, model="text-embedding-3-small"
    ).data[0].embedding

index.upsert(vectors=[
    {"id": "doc1", "values": embed("PayPal refunds..."),
     "metadata": {"text": "PayPal refunds...", "source": "refunds.pdf"}},
])

# Query
query_vec = embed("How long does a PayPal refund take?")
results = index.query(vector=query_vec, top_k=3, include_metadata=True)
for match in results.matches:
    print(match.score, match.metadata["text"])
Chapter 04

RAG — Retrieval-Augmented Generation

Plain English Analogy

RAG is an open-book exam. The LLM (student) no longer has to rely purely on memory. Before answering, it looks up relevant pages from a knowledge base (the book), then writes an answer grounded in real text.

4.1 The RAG Architecture

End-to-end RAG Flow

═══ INDEXING PHASE (offline, one-time) ══════════════════════ 📄 Source Documents │ ▼ [Chunking] Split text into overlapping segments │ ▼ [Embedding Model] Convert each chunk → dense vector │ ▼ [Vector Database] Store vectors + original text + metadata ═══ QUERY PHASE (real-time, per request) ════════════════════ ❓ User Question │ ▼ [Same Embedding Model] Embed the question → query vector │ ▼ [ANN Search] Find top-K similar chunks in VectorDB │ ▼ [Context Assembly] Format retrieved chunks into a prompt │ ▼ 🤖 LLM Generate grounded answer from context │ ▼ ✅ Answer + Sources

4.2 Minimal RAG in 30 Lines

python · langchain + openai + chromadbfrom langchain.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Chroma
from langchain.chat_models import ChatOpenAI
from langchain.chains import RetrievalQA

# 1. Load document
loader = PyPDFLoader("paypal_policy.pdf")
docs = loader.load()

# 2. Split into chunks
splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200
)
chunks = splitter.split_documents(docs)

# 3. Embed + store
vectordb = Chroma.from_documents(
    chunks,
    embedding=OpenAIEmbeddings(),
    persist_directory="./chroma_db"
)

# 4. Build RAG chain
qa = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(model="gpt-4o", temperature=0),
    retriever=vectordb.as_retriever(search_kwargs={"k": 4}),
    return_source_documents=True
)

# 5. Query
result = qa.invoke("What is PayPal's refund timeline?")
print(result["result"])       # LLM answer
print(result["source_documents"])  # chunks used

4.4 Advanced RAG Techniques

Hybrid Search

Combine BM25 keyword search + vector search. Re-rank with RRF (Reciprocal Rank Fusion). Catches exact matches that semantic search misses.

HyDE

Hypothetical Document Embeddings. Ask LLM to generate a hypothetical answer, embed that, use it as the query vector. Better for abstract questions.

Multi-Query Retrieval

Generate 3–5 paraphrases of the query. Retrieve for each. Deduplicate results. Reduces sensitivity to exact phrasing.

Re-ranking

Use a cross-encoder (Cohere Rerank, BGE reranker) to re-score the top-K results. Cross-encoders see both query + doc together.

Parent-Child Chunking

Retrieve small child chunks for precision, but return their parent chunk for context. Best of both worlds.

Self-RAG

Model decides whether to retrieve at all. Generates reflection tokens like [Retrieve], [Relevant], [Supported] to guide the process.

Pipelines — Connecting the Pieces

5.1 LangChain LCEL Pipeline

python · langchain expression language (LCEL)from langchain.schema.runnable import RunnablePassthrough
from langchain.prompts import ChatPromptTemplate
from langchain.chat_models import ChatOpenAI
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Qdrant

# Setup
vectorstore = Qdrant.from_existing_collection(
    embedding=OpenAIEmbeddings(), collection_name="paypal_docs"
)
retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

# Prompt template
prompt = ChatPromptTemplate.from_template("""
You are a PayPal support agent. Use only the context below.
If the answer is not in context, say "I don't have that info."

Context:
{context}

Question: {question}
Answer:""")

# LCEL chain (pipe syntax)
chain = (
    {"context": retriever | (lambda docs: "\n\n".join(d.page_content for d in docs)),
     "question": RunnablePassthrough()}
    | prompt
    | ChatOpenAI(model="gpt-4o", temperature=0)
)

response = chain.invoke("How do I dispute a charge?")
print(response.content)

python · llamaindexfrom llama_index.core import VectorStoreIndex, SimpleDirectoryReader

Chunking is one of the most impactful decisions in RAG. Too small = lost context. Too large = noisy retrieval. The optimal chunk size depends on your documents and query type.

6.1 Strategy Reference

SentenceSplit at sentence boundaries (SpaCy/NLTK)QA over factual text3–10 sentences
Markdown/HTMLSplit at headers, sectionsDocumentation, wikis, HTML pagesPer section

Enhancing LLMs — Techniques

7.1 Prompt Engineering Techniques

Chain-of-Thought (CoT)

Add "Think step by step" to your prompt. Dramatically improves reasoning on math, logic, multi-step problems. Activates internal scratchpad.

Few-Shot Prompting

Provide 2–5 examples of input → output in the prompt. The model pattern-matches to your examples. Best for formatting, classification, extraction.

System Prompt Design

Set role, constraints, output format, tone, and persona in the system message. Use XML tags to structure multi-part prompts. Be explicit, not implicit.

7.3 Agentic Patterns (Tool Use)

ReAct Pattern

Reason → Act → Observe loop. LLM decides when to call a tool, reads the output, decides next step. Used in LangChain Agents, AutoGPT, etc.

Tool Calling (Function Calling)

OpenAI/Anthropic native APIs let you define tools as JSON schemas. Model returns structured tool calls. You execute, return result, model continues.

python · openai tool callingtools = [{
    "type": "function",
    "function": {
        "name": "search_paypal_docs",
        "description": "Search PayPal policy documents",
        "parameters": {
            "type": "object",
            "properties": {"query": {"type": "string"}},
            "required": ["query"]
        }
    }
}]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "What's the dispute window?"}],
    tools=tools,
    tool_choice="auto"
)

# Model returns tool_call if it needs to search
if response.choices[0].message.tool_calls:
    tool_call = response.choices[0].message.tool_calls[0]
    query = tool_call.function.arguments  # JSON string
    # → call your vector search here
    # → send result back as tool message
    # → get final answer from model

7.4 Guardrails & Safety

Input Guardrails

Classify / filter user input. Detect prompt injection, PII, jailbreak attempts before hitting the LLM.

Output Guardrails

Validate LLM output before returning. Check for hallucinations, restricted topics, malformed JSON, PII leakage.

Libraries

Guardrails AI — schema validation. NeMo Guardrails — Nvidia's safety framework. Rebuff — prompt injection detection.

9.4 Cost Optimization Tips

📦 Reduce Token Usage

  • Compress context: summarize chunks before injecting
  • Use smaller models for classification tasks
  • Limit K in retrieval (4 chunks often beats 10)
  • Cache repeated queries semantically

⚡ Reduce Latency

  • Stream responses (first-token latency matters)
  • Parallelize retrieval + pre-processing
  • Use local embedding models (no network hop)
  • Async Python (httpx, asyncio) end-to-end
